# Coralink — запуск через Tailscale (архитектура внедрения)

Документ описывает, как запустить Coralink «в одну ссылку» через Tailscale,
без публичного домена, без проброса портов и без вложений. Это путь для
личной/семейной беты, где все устройства находятся в одном tailnet.

---

## 1. Что меняется в архитектуре

| Слой | Было (локально) | Стало (Tailscale) |
|------|-----------------|-------------------|
| Адрес API | `127.0.0.1:8080` зашит при сборке | Настраивается в приложении в рантайме (поле «Ссылка сервера») |
| Транспорт | HTTP + cleartext | HTTPS (`*.ts.net`) через `tailscale serve` |
| WebSocket | `ws://…/ws` | `wss://<host>/ws` (выводится из ссылки автоматически) |
| Регистрация | телефон + SMS-код | никнейм + имя/фамилия + **пароль** |
| Доступ | только эта машина | любой деvice из tailnet по стабильному имени |

Ключевое: адрес сервера больше не «пекается» в сборку. Приложение читает его из
сохранённых настроек (`AppSettings.serverUrl`), а `AppConfig.withBaseUrl()`
пересобирает и HTTP-base, и `wss://…/ws` на лету. Поэтому один и тот же APK/EXE
подходит любому tailnet — достаточно вставить ссылку.

## 2. ролевая модель tailnet

```
        ┌──────────────────────── tailnet (WireGuard mesh) ────────────────────────┐
        │                                                                           │
        │   [Домашний ПК = сервер]                [Телефон / второй ПК = клиенты]   │
        │   Coralink server                       Flutter app + Tailscale           │
        │   node src/index.js  127.0.0.1:8080      wss/https ──► ts.net             │
        │        ▲                                                            │      │
        │        │ tailscale serve (HTTPS на 443, бесплатный ts.net-сертификат)◄─────┘
        │   https://<machine>.<tailnet>.ts.net                                   │
        └─────────────────────────────────────────────────────────────────────────┘
```

* Сервер слушает **только** `127.0.0.1:8080` — наружу ничего не торчит.
* `tailscale serve` поднимает HTTPS на 443 с валидным сертификатом Let's Encrypt
  (`*.ts.net`) и проксирует на локальный 8080. Это снимает ограничение Android
  на cleartext-HTTP и даёт «одну ссылку».
* Оба клиента должны стоять в **том же** tailnet — иначе не увидят `ts.net`-имя.

### Сосуществование с AmneziaVPN (ответ на вопрос «не помешает ли?»)
Amnezia и Tailscale — оба WireGuard, но в разных диапазонах: Tailscale занимает
`100.64.0.0/10` и разрешает `*.ts.net` через свои DNS. Как правило конфликтов
нет. Проверьте на телефоне: при включённом Amnezia зайдите по ссылке — если не
открывается, в настройках Tailscale у клиента включите `Exit node = off` и
разрешите split-tunnel для `100.64.0.0/10` в Amnezia. На ПК обычно работает
«из коробки».

## 3. Что нужно подготовить (чек-лист)

1. **Tailscale-аккаунт** — https://login.tailscale.com (бесплатный Personal: до
   3 пользователей / 100 устройств).
2. **Домашний ПК-сервер**: Windows 10/11, Node.js **24+**, установленный и
   залогиненный Tailscale.
3. **Клиенты**: Tailscale на телефоне (Play Market / App Store) и на втором ПК,
   вход в тот же аккаунт/tailnet.
4. **Сборки приложения**: можно не пересобирать под ссылку — ссылка вводится в UI.
   (При желании можно зашить дефолт через `--dart-define=API_URL=https://…`.)

## 4. Запуск сервера одной командой (домашний ПК)

Скрипт в корне проекта: [`start-coralink.ps1`](../start-coralink.ps1) (+ ярлык
двойного клика [`start-coralink.cmd`](../start-coralink.cmd)). Идемпотентен:
проверяет Node/Tailscale, при остановленном Tailscale запускает `tailscale up` и
после входа продолжает в том же прогоне (если вход не завершён — попросит
повторить запуск), генерирует
`server/.env` с криптостойкими секретами (JWT_SECRET, AUTH_PEPPER), ставит
зависимости, запускает сервер на `127.0.0.1:8080` (PID в `server/.server.pid`),
публикует его через `tailscale serve` и печатает готовую ссылку.

```powershell
# запуск (или двойной клик по start-coralink.cmd)
powershell -ExecutionPolicy Bypass -File .\start-coralink.ps1
```

Остановка и статус:
```powershell
powershell -ExecutionPolicy Bypass -File .\start-coralink.ps1 -Stop
powershell -ExecutionPolicy Bypass -File .\start-coralink.ps1 -Status
```

Переменные, которые скрипт пишет в `server/.env`:

| Ключ | Значение по умолчанию | Смысл |
|------|------------------------|-------|
| `NODE_ENV` | `production` | включает проверку секретов |
| `HOST` | `127.0.0.1` | сервер не доступен из LAN напрямую |
| `PORT` | `8080` | локальный порт |
| `JWT_SECRET` | случайные 64 символа | подпись токенов |
| `AUTH_PEPPER` | случайные 64 символа | pepper для scrypt-хеша паролей (и кодов) |
| `DB_PATH` | `server/data/coralink.db` | хранилище |
| `ALLOWED_ORIGINS` | `*` | чтобы web-клиент из браузера работал |

`.env` уже в `.gitignore` — секреты не попадут в репозиторий.

### Вручную (если без скрипта)
```powershell
tailscale up
cd ..\Coralink\server
node --env-file=.env src/index.js      # сервер
tailscale serve --bg 8080              # в отдельном окне / после старта
```

## 5. Как получить «ту самую ссылку» (ts.net)

Ссылка — это HTTPS-имя вашей машины в tailnet. Формат:
`https://<machine>.<tailnet-name>.ts.net`

Как увидеть/включить:
1. Включите **MagicDNS** и **HTTPS certificates** в админке:
   https://login.tailscale.com/admin/dns → включить MagicDNS и «HTTPS Certificates».
2. После `tailscale serve` имя машины доступно автоматически; скрипт печатает
   его (`tailscale status --json` → `Self.DNSName`).
3. Проверка с любого клиента tailnet: откройте ссылку в браузере — должен
   вернуться JSON `{"ok":true,...}` с `/health` (serve сам проксирует на 8080).

## 6. Как создавать ссылку-приглашение в сеть (для других людей/устройств)

Чтобы человек «просто по ссылке» попал в ваш tailnet и смог пользоваться
Coralink, есть два способа в Tailscale. Оба делаются в админке
https://login.tailscale.com/admin .

### Способ A — Shared Network (общая сеть, приглашение по e-mail/ссылке)
1. Админка → **Access Controls / Share nodes** (в разных версиях кнопка
   «Share a node…»).
2. Нажмите **Create shared network** → дайте имя (например `coralink-family`).
3. Выберите, какие ваши узлы (в т.ч. сервер) видны участникам.
4. В **Users** добавьте e-mail человека и **Send invite**.
   Человек получает письмо со ссылкой-приглашением; открывает → ставит
   Tailscale → попадает в сеть. Всё, он «подключился по ссылке».
5. Лимиты бесплатного Personal-плана: до ~3 пользователей. Больше — платный план.

### Способ B — добавление собственного устройства (быстро, для себя)
На новом устройстве установите Tailscale → логин через тот же аккаунт (Google/
GitHub/Microsoft/Apple) или «Log in with a link». Это не «гостевая» ссылка, а
вход своих устройств в один tailnet. Подходит, когда устройств немного и вы
владеете ими всеми.

> Важно: и A, и B требуют, чтобы **на клиенте был установлен Tailscale**.
> Ссылка-приглашение — это вход в сеть, а не «открытый адрес сервера для всех».
> Если нужен доступ без Tailscale у клиентов — это уже **Funnel** (см. §9), но с
> публичным адресом и своими лимитами.

## 7. Настройка приложения (телефон/ПК)

1. Убедитесь, что на устройстве включён Tailscale и виден сервер (открывается
   `https://<machine>.<tailnet>.ts.net/health`).
2. Откройте Coralink → на экране входа в поле **«Ссылка сервера»** вставьте
   `https://<machine>.<tailnet>.ts.net` (скрипт печатает готовое значение).
3. Введите **никнейм** (латиница/цифры, 3–32, точка/подчёркивание), **имя** и
   **фамилию** → «Продолжить». Код подтверждения не нужен.
4. Ссылка сохраняется в настройках; менять можно там же:
   **Настройки → Данные → Ссылка сервера** (требуется перезапуск/перелогин).

### Android — особенности
* HTTPS-сертификат `ts.net` валиден, поэтому cleartext не нужен — системная
  политика `network_security_config` не мешает.
* Добавьте Tailscale в исключения оптимизации батареи (И settings → Battery),
  чтобы фоновое соединение не «засыпало».
* Если Amnezia мешает — см. §2 про split-tunnel.

### Web-сборка
* Открывайте web-билд из браузера **того же** устройства, что в tailnet
  (`http(s)://localhost` при запуске воронка не нужна). `ALLOWED_ORIGINS=*` уже
  выставлен.

## 8. Авторизация: никнейм + пароль

Сейчас вход в приложении — по никнейму и паролю: `POST /api/v1/auth/register`
создаёт аккаунт (ник занят → `409`), `POST /api/v1/auth/login` выдаёт JWT. Пароль
проверяется через scrypt с серверным pepper; на сервере хранится только хеш.
Защита периметра — сам tailnet (никто снаружи не достучится), плюс пароль как
второй фактор.

Мультидевайс: вход тем же никнеймом и паролем на другом устройстве восстанавливает
Signal-идентичность и ключи групп из **зашифрованного бэкапа** (ключ выводится из
пароля через PBKDF2; сервер хранит только шифротекст). Поэтому история и группы
читаются, а safety number не меняется.

Варианты ужесточения:
* вернуть SMS/Email-код (маршруты `/auth/request-code`, `/auth/verify` сохранены);
* включить TURN для звонков за пределами tailnet.

## 9. Альтернатива «публично, без Tailscale на клиентах» — Funnel

Если нужно, чтобы пользователи **не** ставили Tailscale:
```powershell
tailscale funnel 8080
```
Откроет ваш сервер на публичном `https://<machine>.<tailnet>.ts.net`. Тогда
ссылку можно давать кому угодно. Минусы бесплатного тарифа: лимиты по трафику и
числу соединений, домен привязан к tailnet, отсутствие белого списка. Для
«мессенджера для всех» это промежуточный вариант перед настоящим доменом + VPS
(см. `docs/DEPLOYMENT.md`).

## 10. Быстрая диагностика

| Симптом | Причина | Что делать |
|---------|---------|------------|
| «Network unavailable» | ссылка битая / сервер не слушает | откройте `<ссылка>/health` в браузере клиента tailnet |
| Android: сертификат/ошибка соединения | ввели `http://` или голый IP | используйте `https://…ts.net` (serve) |
| Заходит, но «Request timed out» | Amnezia режет `100.64/10` | split-tunnel в Amnezia или выключи VPN на тест |
| `tailscale serve` не поднялся | старая версия CLI | `tailscale serve --bg --https=443 http://127.0.0.1:8080` |
| Нет `ts.net`-имени | MagicDNS/HTTPS выключены | админка → DNS → включить MagicDNS и HTTPS certs |
| Собеседник не виден в поиске | не в том tailnet / другой ник | проверьте `username` и что оба онлайн в Coralink |

Команды-подсказки:
```powershell
tailscale status
tailscale serve status
node --env-file=.env src/index.js   # прямой запуск с логами в консоли
```

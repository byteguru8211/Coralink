# Тестирование Coralink

## 1. Серверные тесты

```bash
cd server
npm test
```

49 тестов (`node:test`), реальные HTTP-запросы и WebSocket-соединения на временном порту и временной БД:

- auth: dev-код, verify, JWT, неверный код, блокировка попыток, обязательная авторизация;
- профиль: валидация имени/about/цвета;
- поиск пользователей, контакты (добавление/список/удаление);
- ключи: загрузка, выдача bundle, одноразовое расходование prekey, повторный запрос → `no_keys`;
- очередь сообщений, ack, read receipt;
- WS: отказ без токена, `ready`, онлайн-доставка, ack, офлайн-очередь, signal/typing/presence, `peer_offline`, идемпотентность;
- CORS preflight, rate limit, видимость присутствия (everyone/contacts/nobody);
- `control`-конверты, ICE-метаданные, удаление аккаунта `DELETE /me`;
- heartbeat клиента: `ping` → `pong` (без ошибки `unknown_type`);
- миграция легаси-БД: старт без `username`/`avatar`/`password_hash`, снятие `NOT NULL` с `phone`, сохранение пользователей (`test/migration.test.js`).

## 2. Клиентские тесты

```bash
cd app
flutter test
```

14 тестов:

- `test/widget_test.dart` — валидация и маскирование телефона, инициалы;
- `test/echo_test.dart` — синонимы, опечатки, стоп-слова, round-trip модели сообщения, маппинг `video_note`;
- `test/signal_test.dart` — реальный обмен X3DH/Double Ratchet между двумя хранилищами, расходование prekey, сериализация состояния;
- `test/key_backup_test.dart` — round-trip зашифрованного бэкапа ключей и отказ на неверном пароле.

`flutter analyze` должен завершаться без ошибок (допустимы info-подсказки линтера).

## 3. E2E двух клиентов

Требуется запущенный сервер:

```bash
cd server
rm -f data/e2e.db*
NODE_ENV=development DEV_MODE=true PORT=8080 DB_PATH=./data/e2e.db \
JWT_SECRET=e2e-jwt-secret-with-more-than-thirty-two-characters \
AUTH_PEPPER=e2e-auth-pepper-with-more-than-thirty-two-characters \
node src/index.js
```

В другом терминале:

```bash
cd app
flutter test integration_test/e2e_test.dart -d windows
```

> Офлайн-среда: `integration_test` тянет androidx.test из Google Maven. Если
> Maven недоступен, этот E2E не соберётся — тогда ограничьтесь `flutter test`
> (юнит/виджет) и `node --test` (сервер), а на время сборки release APK временно
> уберите `integration_test` из `pubspec.yaml`.

Тест:

1. регистрирует двух пользователей;
2. публикует Signal-ключи;
3. отправляет E2EE-сообщение A→B и проверяет расшифровку;
4. отправляет B→A (двусторонний ratchet);
5. отключает B, отправляет сообщение, проверяет офлайн-очередь и что в очереди только шифротекст;
6. переподключает B, синхронизирует очередь и проверяет сохранение.

> Rate limit сервера — 5 кодов/час на IP. Для повторных прогонов перезапустите сервер (лимиты в памяти) или используйте свежий IP.

## 4. Ручной чек-лист

### Вход
- [ ] Неверный номер → подсветка/подсказка.
- [ ] Код 6 цифр, авто-переход между ячейками, вставка из буфера.
- [ ] Неверный код → сообщение, поле очищается.
- [ ] Повторная отправка кода доступна после таймера.
- [ ] Новый пользователь → экран имени; повторный вход → сразу чаты.
- [ ] Перезапуск приложения сохраняет сессию.

### Чаты
- [ ] Пустое состояние с кнопкой «Найти друзей».
- [ ] Поиск по номеру, открытие чата, добавление в контакты.
- [ ] Отправка текста, шифрование, статусы «отправлено/доставлено/прочитано».
- [ ] Второй клиент получает сообщение в реальном времени.
- [ ] Офлайн-получатель: сообщение ждёт и приходит после подключения.
- [ ] Печатает…, присутствие, ореол.
- [ ] Свайп чата влево → архив, возврат из «нижнего слоя».
- [ ] Долгое нажатие → закрепить/архив/без звука/удалить.
- [ ] Фото из галереи, ограничение 350 КБ.
- [ ] Реакции-капли, удаление у себя и у всех.
- [ ] «Показать архив (N)» для старых сообщений.
- [ ] Эхолокация находит сообщение по синониму/опечатке.

### Настройки
- [ ] Тёмная/светлая/системная темы.
- [ ] RU/EN без перезапуска.
- [ ] 4 режима уведомлений, предупреждение при отказе в разрешении.
- [ ] Звуки: выбор отдельного звука для присутствия/отправки/получения/звонка, «без звука», громкость, пример.
- [ ] Приватность: кто видит статус, удаление аккаунта.
- [ ] Очистка кэша, экспорт чатов (файл в Documents).
- [ ] Выход и повторный вход.

### Платформы
- [ ] Android: установка APK, уведомления, камера/галерея.
- [ ] Windows: запуск .exe, звуки, WebRTC, иконка в трее, сворачивание по крестику в трей.
- [ ] Звонок: экран с таймером и кнопками (микрофон/динамик/камера/смена камеры/сброс), история звонков плашками в ленте у обеих сторон.
- [ ] Группа: иконка выбирается при создании, участник получает уведомление и группа сразу появляется в списке.
- [ ] Web: вход, чат, предупреждение о неподдерживаемом экспорте.

## 5. Диагностика

| Симптом | Причина/решение |
|---|---|
| `No connection to the server` | сервер не запущен / неверный `API_URL` |
| Android не видит сервер | используйте `10.0.2.2`, проверьте cleartext-config |
| `429 Too many requests` | лимит кодов; перезапустите dev-сервер или подождите |
| `no_keys` | собеседник ещё не опубликовал ключи; пусть откроет приложение |
| `identity_changed` | у собеседника новый набор ключей (переустановка); нужен сброс сессии |
| Web-пусто после перезагрузки | web-история хранится в памяти — это ожидаемо |
| APK не ставится | удалите старую версию (`adb uninstall com.coralink.app`) |
| Сборка падает на Kotlin-кеше | в `android/gradle.properties` уже стоит `kotlin.incremental=false` |
